# mobile-build

The app is `apps/mobile` (Expo SDK 58, React Native 0.88, TypeScript strict, jest, ESLint with the accessibility rule set). It is one workspace of the pnpm monorepo. **The native projects (`android/`, `ios/`) are generated by `expo prebuild` from `app.config.ts` and are never committed** (`apps/mobile/.gitignore`). The pack ships a placeholder identity (`com.example.app`); step 6 replaces it. Pins and their sources: `${CLAUDE_SKILL_DIR}/references/sources.md`.

## Checks (run from the repository root; `pnpm` = `npx --yes pnpm@11.28.8` when not installed)

| Check | Command | Where |
|---|---|---|
| Install | `pnpm install --frozen-lockfile` | local, CI |
| Lint (accessibility) | `pnpm --filter @app/mobile lint` | local, CI |
| Types | `pnpm --filter @app/mobile typecheck` | local, CI |
| Tests | `pnpm --filter @app/mobile test` | local, CI |
| Prebuild | `pnpm --filter @app/mobile exec expo prebuild --no-install --platform android` (and `ios`) | local, CI |
| Android debug build | `cd apps/mobile/android && ./gradlew assembleDebug` | CI on Linux (JDK 17, Android SDK platform 36), or any machine that has them |
| iOS simulator build, unsigned | `cd apps/mobile && npx expo prebuild --platform ios && xcodebuild -workspace ios/<App>.xcworkspace -scheme <App> -configuration Debug -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build` | CI on a macOS runner (Xcode and CocoaPods are on the image) |

A machine without Xcode or the Android SDK proves the first five rows; the two native builds are proven in CI. Say which ran. Do not install Xcode or the Android SDK to "make it work" without asking.

## Rules

1. **Gate 4 includes accessibility (spec 9.1).** `eslint-plugin-react-native-a11y` runs on every PR (Biome cannot lint React Native accessibility, so `apps/mobile` has its own `eslint.config.mjs`; the rest of the repo stays on Biome). Every touchable has a role and a label; every image has a label or is hidden from screen readers; every state (loading, error, update-required) has a label a screen reader reads. A rule is never switched off to pass (all rules are set to `error`); a new `off` needs a recorded reason. The plugin does not see a role-only `Pressable` (a role without `accessibilityLabel` on a pressable wrapper is not flagged by every rule), so review such components by hand and prefer `accessibilityLabel` plus `accessibilityRole` together. If the plugin ever blocks an ESLint upgrade, the fallback is the flat-config fork `Volksverpetzer/eslint-plugin-react-native-a11y` (see sources). Screen-reader and device checks stay manual (step 10 list).
2. **Minimum supported app version (spec 11.4).** The API sends `X-Min-App-Version` (plain `MAJOR.MINOR.PATCH`, setting `MIN_APP_VERSION`, default `0.0.0`) on every response. The app reads it from `/healthz` (also on errors), compares it with `expo-constants` `version`, and below it shows the blocking "Please update" screen: no button, no link, no way past. A missing or malformed header never blocks. Raise `MIN_APP_VERSION` only after the new build is live in both stores; the API keeps serving every version at or above it (`DEPLOYMENT.md` release rule). A new mobile API call goes through the same client so the header is seen on every response.
3. **Config is public.** `app.config.ts` `extra` ships inside the app: the API base URL (`EXPO_PUBLIC_API_BASE_URL`) and nothing else. Never an API key, token or secret.
4. **No signing material, EAS project id or store configuration is committed.** No `.p12`, `.jks`, `.keystore`, `.mobileprovision`, `.p8`, no `eas.json` with a `projectId`. A static test of the pack fails on any of them.
5. **EAS only through ask-before-adding.** Expo's hosted build and submit service (EAS) is a new billable service: say what it is, what it does, why GitHub Actions does not, and its verified cost, then wait. Until approved, builds run in GitHub Actions.
6. **Store submission is a founder step.** An agent builds and signs; it never creates the developer accounts, accepts the store agreements, creates the store listing, uploads a build to review or presses "submit". It writes the step into `WAITING.md` with the artifact path and what it unblocks. Store lead times are in the lead-time register.

## Ruling 8: CI for mobile

Android debug build on Linux; an unsigned iOS simulator build on macOS runners **only if they are free**. Checked 2026-11-09 at https://docs.github.com/en/actions/reference/runners/github-hosted-runners : "Use of the standard GitHub-hosted runners is free and unlimited on public repositories", and the public-repository table lists macOS arm64 (`macos-latest`, `macos-15`, `macos-26`; 3 CPU, 7 GB) and Intel (`macos-15-intel`, `macos-26-intel`). Larger runners are billed. So: in a **public** repository the iOS job runs; in a **private** repository macOS minutes are billed and the job stays off until the founder approves the cost (ask-before-adding). The mobile job runs on pull requests that touch `apps/mobile` (and the API contract), and weekly.

## Signing (release jobs only)

Material and where it lives (GitHub encrypted secrets, in an environment named `release` with required reviewers; never in the repository, never on a pull request from a fork): iOS distribution certificate `IOS_CERT_P12_BASE64` and `IOS_CERT_PASSWORD`, provisioning profile `IOS_PROFILE_BASE64` (or an App Store Connect API key `ASC_KEY_P8_BASE64`, `ASC_KEY_ID`, `ASC_ISSUER_ID`), Android `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. **Owner, creation date and rotation interval of each go into `SERVICES.md`** (never a value); certificates and profiles expire, so the rotation date is a dated reminder in `WAITING.md`.

**iOS: a temporary keychain per job, deleted afterwards.** Secrets reach the step as environment variables and are never echoed. One exception cannot be avoided: the `security` CLI takes `create-keychain -p`, `unlock-keychain -p`, `set-key-partition-list -k` and `import -P` as command-line arguments, so the values are visible in the process list for the length of each call. That is acceptable only on GitHub-hosted runners (single-tenant, destroyed after the job); a signing job never runs on a self-hosted runner. The keychain password is a throwaway `uuidgen` value; only the certificate password is a real secret.

```bash
KEYCHAIN="$RUNNER_TEMP/build.keychain-db"; KEYCHAIN_PASSWORD="$(uuidgen)"
security create-keychain -p "$KEYCHAIN_PASSWORD" "$KEYCHAIN"
security set-keychain-settings -lut 21600 "$KEYCHAIN"
security unlock-keychain -p "$KEYCHAIN_PASSWORD" "$KEYCHAIN"
umask 077
echo "$IOS_CERT_P12_BASE64" | base64 --decode > "$RUNNER_TEMP/cert.p12"; chmod 600 "$RUNNER_TEMP/cert.p12"
security import "$RUNNER_TEMP/cert.p12" -P "$IOS_CERT_PASSWORD" -A -t cert -f pkcs12 -k "$KEYCHAIN"
security set-key-partition-list -S apple-tool:,apple: -k "$KEYCHAIN_PASSWORD" "$KEYCHAIN" > /dev/null
security list-keychains -d user | tr -d '"' > "$RUNNER_TEMP/keychains.orig"   # saved for the cleanup
security list-keychains -d user -s "$KEYCHAIN" login.keychain-db
mkdir -p "$HOME/Library/MobileDevice/Provisioning Profiles"
echo "$IOS_PROFILE_BASE64" | base64 --decode > "$HOME/Library/MobileDevice/Provisioning Profiles/ci.mobileprovision"
# only when the App Store Connect API key is used:
mkdir -p "$RUNNER_TEMP/asc"; echo "$ASC_KEY_P8_BASE64" | base64 --decode > "$RUNNER_TEMP/asc/AuthKey_$ASC_KEY_ID.p8"; chmod 600 "$RUNNER_TEMP/asc/AuthKey_$ASC_KEY_ID.p8"
```

Then the signed archive (`xcodebuild archive` with the team and profile named in `ExportOptions.plist`). Cleanup is a separate step with `if: always()` so a failed build still removes everything:

```bash
# restore the keychain search list saved before the import, then delete the temporary keychain
[ -s "$RUNNER_TEMP/keychains.orig" ] && xargs security list-keychains -d user -s < "$RUNNER_TEMP/keychains.orig" || true
security delete-keychain "$RUNNER_TEMP/build.keychain-db" || true
rm -rf "$RUNNER_TEMP/asc" "$RUNNER_TEMP/keychains.orig"
rm -f "$RUNNER_TEMP/cert.p12" "$HOME/Library/MobileDevice/Provisioning Profiles/ci.mobileprovision"
```

**Android: the keystore is decoded to a temporary file removed in an `always()` step.** `umask 077; echo "$ANDROID_KEYSTORE_BASE64" | base64 --decode > "$RUNNER_TEMP/release.jks"; chmod 600 "$RUNNER_TEMP/release.jks"`; Gradle reads its path and passwords from `ORG_GRADLE_PROJECT_*` environment variables; the cleanup step runs `rm -f "$RUNNER_TEMP/release.jks"` under `if: always()`. A job needing a secret has `permissions: contents: read` only and runs on a GitHub-hosted runner, which is destroyed after the job; the explicit deletion is a second line.

**Release job rules.** The release/signing job is guarded by a protected GitHub environment (`release`) with required reviewers, is triggered only by a tag or a manual dispatch, and never runs on `pull_request` (above all from forks). It never runs on a self-hosted runner.

The signed archive and the signed Android bundle are the output of the release job (an artifact). Uploading them to a store is a **founder step** (rule 6).

## Steps

1. Read `docs/spec/SPEC.md` (mobile features), the contract, `DESIGN.md` (screens, "please update" screen) and decision 0005. If mobile is not a surface, stop: nothing here applies.
2. Slice work: red test first (jest), then code; run the first five checks; the PR line names which native builds ran.
3. Changing the app identity or adding a native module: `expo prebuild --clean` locally, then the Android build in CI; record the new bundle id in `SERVICES.md` and `WAITING.md` (store accounts are founder steps).
4. Releases: tag, release job (signing above), artifact, then the founder submits.
