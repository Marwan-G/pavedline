# Sources and pins for the local-cluster backup stack (`up.sh --full`)

Checked 2026-11-09. The pins live in `scripts/local-cluster/versions.env`; Argo CD, CloudNativePG, Gateway API and Envoy Gateway are in `skills/gitops/references/sources.md`.

| Fact | Value | Source |
|---|---|---|
| CloudNativePG operator | Chart 0.29.1 ships operator 1.30.1 (`helm show chart`); the Barman Cloud plugin needs CloudNativePG 1.26 or newer. The in-tree `barmanObjectStore` is deprecated and removed in 1.32, so backups use the plugin only. | https://cloudnative-pg.io/plugin-barman-cloud/docs/installation/ |
| Barman Cloud plugin | Apache-2.0, v0.15.1 released 2026-09-30 (v0.15.0 2026-09-03). Installed in the operator's namespace `cnpg-system` from the release manifest `https://github.com/cloudnative-pg/plugin-barman-cloud/releases/download/v0.15.1/manifest.yaml`, sha256 `8f377ff4a7d0d3f74fc64b0f7ac4f449fc38ca9e83a40107cca2f9315a9bd920`. The manifest names its images by tag; `up.sh` moves them to digests: `ghcr.io/cloudnative-pg/plugin-barman-cloud:v0.15.1@sha256:c75acad19a36e8176cfe2885761ff1b836c6ef977d7257e298c99a28b5c302ef` and the sidecar `ghcr.io/cloudnative-pg/plugin-barman-cloud-sidecar:v0.15.1@sha256:2287a793a804db751edd0d07d44cd549e357677e98a800eb12e2cf7c0d53f9b0` (multi-arch indexes: linux/amd64 and linux/arm64; digests read from the registry API 2026-11-09). | https://github.com/cloudnative-pg/plugin-barman-cloud/releases |
| Plugin objects | `ObjectStore` (`barmancloud.cnpg.io/v1`): `spec.configuration.{destinationPath, endpointURL, s3Credentials.{accessKeyId,secretAccessKey}, wal.compression}`, `spec.retentionPolicy` (`[1-9][0-9]*[dwm]`, from the CRD in the manifest), `serverName` stays empty. `Cluster.spec.plugins: [{name: barman-cloud.cloudnative-pg.io, isWALArchiver: true, parameters: {barmanObjectName}}]`. `Backup` / `ScheduledBackup`: `method: plugin`, `pluginConfiguration.name: barman-cloud.cloudnative-pg.io`. Restore into a new cluster: `bootstrap.recovery.source` + `externalClusters[].plugin` with `barmanObjectName` and `serverName` (the source cluster's name); the recovered cluster does not archive WAL unless it gets its own `plugins` section. | https://cloudnative-pg.io/plugin-barman-cloud/docs/usage/ and /docs/concepts/ |
| cert-manager | Apache-2.0. v1.21.3 released 2026-10-23 (the newest release at least two weeks old; v1.20.5 of 2026-10-28 is not). Chart `oci://quay.io/jetstack/charts/cert-manager` v1.21.3, digest `sha256:e482675aec32862d323a9218293ff7de81192337998615e4378c56498473f240` (`helm show chart` output); installed with `crds.enabled=true`. The plugin manifest contains cert-manager `Certificate` and `Issuer` objects, so cert-manager must be present first. | https://github.com/cert-manager/cert-manager/releases , https://cert-manager.io/docs/installation/helm/ |
| SeaweedFS | Apache-2.0, active (MinIO's community edition is archived). 4.51 released 2026-10-25 (15 days old; 4.52 of 2026-11-02 and 4.53 of 2026-11-08 are too new). Image `chrislusf/seaweedfs:4.51@sha256:f7a49e3f3972ebed5be2ed4befa4a0c68eb7bdddba6e692d42729ceb545134b8` (multi-arch index incl. linux/arm64 and linux/amd64). `weed server -s3 -filer -s3.config=<identity json>`; an `Admin` identity creates a bucket on first upload (`-s3.autoCreateBucket`, default on); checked with an S3 client against the image on 2026-11-09. It is a local tool in the throwaway cluster, not a service. | https://github.com/seaweedfs/seaweedfs/releases , https://github.com/seaweedfs/seaweedfs/wiki/Amazon-S3-API |
